Reproduce a Receipt

RE-DERIVE THE AMOUNT IN YOUR OWN BROWSER · WORKS OFFLINE

Paste a receipt link, or drop the JSON files you saved with curl (HUB_VERIFY.md). This page runs the exact same code as scripts/reproduce-receipt.cjs — it fetches only public JSON, re-derives the amount on your own machine, and never sends your inputs anywhere. Once the page has loaded, the offline path needs no network at all.
Reproduce
A receipt page or its JSON, e.g. https://clucknorris.app/hub/cuna/r/<sig>.
A URL on a different host than this page (e.g. checking a staging receipt from production) needs that host to allow cross-origin reads — the public Hub JSON routes do; a private or gated route will not.
Drop receipt.json plus batch-inputs.json (lock-to-earn) or standings.json (buy competition) — saved exactly as HUB_VERIFY.md §c shows. A program-version.json is optional and only used to recompute that version's own hash (§d). Or drop a single evidence bundle (the "download the evidence bundle" link on any batch or receipt page) — it carries all of that in one file and reproduces every receipt in the batch at once.

What this proves — and does not
What a MATCH proves: the payout amount is exactly reproducible from inputs the server itself published — the accrual periods, what was already paid or held elsewhere, and (for a buy competition) the sealed terms and this wallet's own reviewed buy. Nobody has to trust a number on a page; it can be recomputed by anyone, offline, forever.
What it does not prove: that the server omitted no qualifying wallet from the calculation in the first place, or that the published inputs were never edited before you fetched them. That second guarantee needs the program version's hash to be independently committed on-chain by the project's own funding wallet — reproducible from published inputs is the first rung, not the whole ladder, and no real program has that on-chain commitment live yet.
