## 1. Security — from an external scan (rootcrak), 2026-08-01

The scan reported 6 findings. **4 of the 6 were already fixed and its remediation steps assume
Firebase Hosting; this is Express on Railway.** Verify against the live headers before acting on any
future report from it:

```
curl -sI https://clucknorris.app/ | grep -iE 'content-security|strict-transport|x-frame|x-content|referrer'
```

Already sent, and were before the scan ran: `Strict-Transport-Security`, `X-Frame-Options:
SAMEORIGIN`, `X-Content-Type-Options: nosniff`, `Referrer-Policy`.

### 1a. CSP is shipped but weakened by `'unsafe-inline'` — the real follow-up
`0ec4bc6` added a Content-Security-Policy (see the block above the middleware in `server.js` for why
each directive is what it is). It pins the only four external script origins, and sets
`object-src 'none'` + `base-uri 'self'`.

**It cannot stop an XSS that injects _inline_ JS**, because every tool page is vanilla HTML with
inline `<script>`. Closing that means per-request nonces on every inline block across ~20 pages.
That is the highest-value security work left, and it matters here specifically because the forensic
tools render **attacker-controlled token names and symbols**. Do it deliberately, not as a quick fix.

⚠️ **Verification status is partial, be honest about it.** 20 pages were loaded in a real browser
against a LOCAL server: 0 violations. The same check against **production could not be run** — this
container's browser gets `net::ERR_CONNECTION_RESET` for every external host, so a "0 violations"
result there is meaningless (the pages never loaded). **Re-run the browser check against
clucknorris.app from somewhere with real network access** before considering CSP verified in prod.

### 1b. No WAF (CVSS 7.0) — OWNER DECISION, needs DNS access
The only finding that is both real and unaddressed. Nuance the scan missed: Railway's edge does
front the app (`server: railway-hikari`, `x-railway-edge`), so the origin is not nakedly exposed —
but Railway's edge is **not** a WAF (no OWASP ruleset, no bot-fight mode).

Already mitigating the money risk: per-IP sliding-window rate limits on the paid endpoints —
`/api/` 150/min, AI paths 12–15/min, forensics 15/min.

If the owner wants Cloudflare free tier, the **safe order** (getting this wrong takes the site down
and can break Railway deploys): add domain → set SSL/TLS to **Full (strict)** so Railway's cert
still validates → proxy the root record → *then* Bot Fight Mode + WAF rules. Requires the DNS panel.

### 1c. HSTS `preload` — OWNER DECISION, deliberately not done
We send `max-age=31536000; includeSubDomains` but not `preload`. Adding the word is meaningless
without submitting at hstspreload.org, and **submitting is close to irreversible** — removal takes
months of browser releases, and with `includeSubDomains` every future subdomain must serve valid
HTTPS from day one. Not a scanner's call.

### 1d. `Permissions-Policy` is not sent
Minor, unflagged, cheap. Something like `camera=(), microphone=(), geolocation=(), payment=()`.

because boss code is shared.

### 2a. Harness gap that let the dragon bug ship green
`__NQ_STOMPTEST` used to report `stompable` from `wouldStomp()` alone — it never asked whether the
two physics bodies **can overlap** where a player aims. It now also reports `headGap`,
`headGapPct`, `stompBandPx` and `hitW/drawnW`. Those numbers immediately ranked the roster and found
12-3. **When adding a boss, check `headGap`, not just `stompable`.**

### 2b. Route trap that cost a wrong diagnosis
The game is served at **`/normie-quest-x7`**. `/normie-quest-play.html` **404s in production** — it
is only a build artifact name. Grepping that URL for markers returns 0 forever and looks exactly
like a stalled deploy. It led to a false "deploy dead 13 hours" call and an unnecessary
`chore: nudge Railway` commit (`b88ae62`). Also: a 10 MB page needs a generous `curl --max-time`, or
the truncated body produces the same false negative.
