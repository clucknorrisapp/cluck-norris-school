## 1. Permissions — the answer, after it cost hours

**Two independent systems. Only one is in this repo.**

**Claude Code** — `.claude/settings.json`. Now: `defaultMode: dontAsk`, blanket `allow`
(`Bash`, `Read`, `Edit`, `Write`, `Glob`, `Grep`, `WebFetch`, `WebSearch`), and `ask` on exactly
five destructive git ops. Rule precedence is **deny → ask → allow**, verified in the CLI's own
evaluator and applied *per subcommand*, so `git push --force` still prompts despite the blanket
`Bash` allow. Done; not the thing that was interrupting anyone.

**The Higgsfield connector** — nothing in this repo can touch it. Per-tool policies live in
`/tmp/mcp-config-cse_<session>.json`:

```
86 Higgsfield tools: 36 always_allow · 46 always_ask · 4 always_deny
generate_image / job_display / media_confirm / show_generations → always_ask
```

Proof it is not local: `permission_policy`, `always_ask`, `always_allow` all appear **0 times** in
`cli.js`. The Anthropic gateway enforces it. Also dead ends, all tested — editing that JSON (read
into memory at session start, regenerated next session), `allowedTools` in `.claude.json` (that's
for skills), `claude mcp` subcommands (no permission command exists), and hitting
`mcp.higgsfield.ai/mcp` directly (**401**, needs OAuth).

**Fix, and it worked:** claude.ai → Settings → Connectors → Higgsfield → set tools to Allow. The
owner did this and it took effect **on connector reconnect, mid-session** — a new session was not
required.

**Lesson worth keeping:** when something is blocked, find the file that governs it before
theorising about why. This one burned most of an afternoon across three wrong explanations.

⚠️ Also: the CLAUDE.md trim of 2026-07-30 did **not** cause any of this. That commit touched one
file (`CLAUDE.md`); `.claude/settings.json` did not exist until 2026-08-01. Don't roll the trim
back looking for a permissions fix.

## 3. Traps found today

- ⛔ **`getParsedTokenAccountsByOwner` is not a JSON-RPC method.** It is a web3.js `Connection`
  *helper*. Production answers it **`-32601 Method not found`**. Use `getTokenAccountsByOwner` with
  `{encoding:'jsonParsed'}` — the `{mint}` filter resolves the owning program, so Token-2022 is
  covered. This shipped as a bug in the Locker Room balance lookup and was caught only by probing
  prod, not by reading code.
- ⚠️ **The locker i18n dictionaries key on the ENGLISH SOURCE STRING** (66 keys × 6 languages).
  Change English copy and that string silently falls back to English everywhere else, with no
  error. Before editing `/locker-room` text, check whether the string is a key in
  `public/i18n/*.locker.json`. Only 4 of the 14 FAQ `<h4>`s are keys.
- **`/` serves `public/home.html`**, not the React app. Route names still mislead; grep first.
- **The lock text-only fallback is 24h**, not 6h (`LOCK_ANNOUNCE_FALLBACK_MS`). It sets
  `announced:true` and **keeps** the payload — it never nulls `pending`.
- **kv IS volume-backed** (`lib/kvstore.js` → `/data/app-state.json`), so a Railway redeploy does
  **not** wipe pending payloads. Don't blame a deploy for missing state.
- **Commits from cloud sessions are unsigned.** `commit.gpgsign=true` and `gpg.format=ssh` are set,
  but `/home/claude/.ssh/commit_signing_key` is **missing** and the `.pub` is 0 bytes. A probe
  commit came out `[N]`. The stop-hook nags every turn; the suggested `--amend --reset-author`
  fixes the *email* (already correct) and cannot create a signature. Nothing to do in-container.
