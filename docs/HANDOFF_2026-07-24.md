### What was just discovered (this is the important part)

`normie-quest/test/nq-geometry-check.cjs` **was only checking 39 of 63 levels.** Its `loadLevels()`
regex matched only the hand-built JSON one-liner format (worlds 9–21). Worlds 1–8 are written as
multi-line JS object literals, so they were skipped — and the checker still printed `RESULT: PASS ✓`.
A false green over the entire free tier and all of tier-1 premium.

Fixed in `4737faa`: the loader now evaluates the `LEVELS` array directly (pure data + the
`H`/`GY`/`TILE`/`W` constants mirrored from `game_logic.js` line 4), which covers both formats.
Coverage 39 → 63.

**The moment it could see worlds 3–8, 56 hard failures appeared.** They were always there.

### Recommended next move

Hand-rebuild **worlds 3–8** to the same bar as 9–21 — that's 18 levels, the entire tier-1 paid
tier, and the tier most likely to generate refund complaints. Worlds 1–2 have **no hard failures**
and only cosmetic warnings (monotonous gap widths, powerup clumping); they're playable today, so

Open question for the owner, worth asking before starting: **rebuild 3–8 in place (fix the 56

My read: 3–8 are the paid tier and their `-3` finales are structurally broken, so from-scratch
for the `-3` levels at minimum.

### How to work on it

- Levels live in `normie-quest/src/game_logic.js`, `var LEVELS=[...]` (starts ~line 349).
- Hand-built levels are **one JSON object per line** — match that format for anything new.
- Build: `node normie-quest/src/build.js`
- Check: `node normie-quest/test/nq-geometry-check.cjs` (add `--json` for machine-readable)
- F1–F12 are hard failures, W1–W9 are warnings. **Get to 0 FAIL; warnings are judgment calls.**
- Prior rebuilds used scratchpad builder scripts (`build_09.cjs` … `build_21.cjs`, `splice.cjs`) —
  those are gone with the old container, but the pattern was: generate the level object in a script,
  splice it into the LEVELS array, re-run the checker, iterate to clean.
- Schema: `plat:[x,count,topY,material]` · `wall:[x,heightTiles,material,?]` · `gaps:[[x1,x2]]` ·
  `spike:[x]` · `coin:[x,y]` · `powerups:[[kind,x,y]]` · `mover:[x,y,axis,range,speed]` ·
  `rugplats:[[x,tiles,topY]]` · `dumpzones:[[x,intervalMs]]` · `key:[x,y]` · `door:x`

## 🪤 Gotchas learned the hard way (all now in CLAUDE.md)

- **Telegram photo/video captions cap at 1024 chars**, not 4096 — and *our own code* slices
  silently, returning `success:true`. Cost us the X link on the first announcement.
- **`public/` is NOT statically mounted** — a new asset needs an explicit `app.get` route, or the
  SPA catch-all serves it as `text/html` and the browser refuses it on MIME type, silently.
  Caught only by loading the page in headless Chromium.
- **A green test can mean the test isn't looking.** Both the MIME bug and the 56 Normie failures
  hid behind passing checks. When something "passes", confirm it actually covered the thing.
